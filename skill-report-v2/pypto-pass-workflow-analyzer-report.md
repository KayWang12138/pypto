## 5. 问题列表

### S1 重大问题

#### 问题 1：工作流关键动作缺少“怎么做”的实现方法

- 命中规则：`R26(S1)`
- 位置：`SKILL.md:70`
- 证据：
  > `4. 绘制业务流执行路径`
- 问题说明：该步骤提出“绘制执行路径”，但未给出绘制方式（例如使用 Mermaid、表格模板、或固定输出结构），执行者难以落地。
- 修改建议（前/后对比）：
  - 修改前：`4. 绘制业务流执行路径`
  - 修改后：`4. 使用 Mermaid 绘制业务流执行路径（至少包含阶段节点、顺序箭头、关键决策点），并在输出中附上代码块。`

### S2 中等问题

#### 问题 2：同一段落附近叠加出现重复标题、缺少理由、缺少成功标准和失败恢复

- 命中规则：`R45(S2)×2`, `R23(S2)`, `R24(S2)`, `R30(S2)`
- 位置：`SKILL.md:66`
- 证据：
  > `### 基础业务流分析`
  > `1. 定位 pass 文档中的业务流介绍部分`
- 问题说明：
  - 标题“基础业务流分析”“视图类OP流程分析（新增）”在文档前后重复出现（R45）。
  - 关键步骤多数仅写“做什么”，未解释“为什么这样做”（R23）。
  - 缺少可验证完成判据，如“提取结果至少包含阶段/顺序/关键决策点”（R24）。
  - 未描述任何异常场景（文档缺失、关键词未命中、解析失败）下的恢复动作（R30）。
- 修改建议（前/后对比）：
  - 修改前：
    - `1. 定位 pass 文档中的业务流介绍部分`
    - `2. 分析业务流的结构和阶段`
  - 修改后：
    - `1. 定位 pass 文档中的业务流介绍部分（原因：该部分是后续阶段拆解的唯一输入）。成功标准：定位到至少1个明确章节标题。失败恢复：若未找到，回退到“目录/章节索引”并记录“未发现业务流章节”。`
    - `2. 分析业务流的结构和阶段（成功标准：输出阶段列表、阶段顺序、每阶段输入输出）。`

#### 问题 3：输出模板段落存在高重复度，信息冗余

- 命中规则：`R14(S2)`
- 位置：`SKILL.md:134`
- 证据：
  > `#### assemble_op_workflow.md 内容`
  > `- 模块1：模块前状态 → 模块处理 → 模块后状态变化`
- 问题说明：`view/assemble/reshape` 三个输出章节内容几乎逐行重复，仅 OP 名称不同，造成维护成本上升。
- 修改建议（前/后对比）：
  - 修改前：分别维护三段近似相同的“*_op_workflow.md 内容”清单。
  - 修改后：抽象成“通用模板 + OP 占位变量”，例如“`<OP_NAME>_op_workflow.md` 通用结构”，并在每个 OP 小节仅保留差异化字段。

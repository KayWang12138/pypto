### S2 中等问题

#### 问题 1：章节出现重复模板，存在冗余
- 命中规则：`[S2] R14`
- 位置：`SKILL.md:251`
- 证据：
  - `**降级条件**（仅以下情况可手动解析）：`
  - `**降级条件**（仅以下情况可使用其他方式）：`
- 问题说明：步骤 1/2/3 中重复出现近乎同构的“降级条件”段落，跨章节信息重复，增加阅读负担。
- 修改建议（before/after）：
  - before：在每个步骤分别重复完整降级条件列表。
  - after：抽取为一个统一小节（如“通用降级策略”），各步骤仅保留差异点并链接该小节。

#### 问题 2：部分被引用文件缺少“加载时机”描述
- 命中规则：`[S2] R19`
- 位置：`SKILL.md:408`
- 证据：`- [错误处理参考](references/error-handling.md) — MCP 错误、平台错误、pre-receive hook 诊断`
- 问题说明：引用了 `references/error-handling.md` 的用途，但未明确“何时加载/查阅”（例如 API 调用失败、hook 报错时立即加载）。
- 修改建议（before/after）：
  - before：仅在“参考文档”列用途。
  - after：补充触发时机，例如“当出现 `pre receive hook check failed` 或 MCP 返回 4xx/5xx 时，立即读取该文档进行分支诊断”。

#### 问题 3：多个流程步骤缺少可验证成功标准
- 命中规则：`[S2] R24`
- 位置：`SKILL.md:44`
- 证据：`6. 对 codecheck 失败：`
- 问题说明：步骤描述了动作，但未统一给出“成功判据”（例如“步骤完成必须产出 violations.json 且 total 字段存在”）。
- 修改建议（before/after）：
  - before：动作导向步骤为主。
  - after：每步补 1 条验收条件（输出文件、关键字段、返回码、下一步输入）。

#### 问题 4：命令与路径包含未解析占位符
- 命中规则：`[S2] R25`
- 位置：`SKILL.md:55`
- 证据：`> 1. 切换到 PR 对应的本地分支：`git checkout <branch_name>``
- 问题说明：`<branch_name>`、`<owner>/<repo>/<number>` 等占位符在执行语境下不可直接运行，缺少“如何替换”的明确约束。
- 修改建议（before/after）：
  - before：直接给占位命令。
  - after：补充变量来源与替换规则，例如“`<branch_name>=pr_info.source_branch`，示例 `git checkout fix/pr-1276-codecheck`”。

#### 问题 5：整体完成标准不够显式
- 命中规则：`[S2] R27`
- 位置：`SKILL.md:389`
- 证据：`PR 创建成功后检查 CLA 和 LGTM 状态：`
- 问题说明：文档描述了提交后检查项，但未给出“任务完成”的统一定义（必须满足哪些条件才算结束）。
- 修改建议（before/after）：
  - before：分散描述流程终点。
  - after：新增“完成标准”小节，明确最小完成集合（如：全部可自动修复项已落地、本地预检通过、PR 已创建、遗留项已结构化 TODO）。

#### 问题 6：多选场景未给默认推荐
- 命中规则：`[S2] R51`
- 位置：`SKILL.md:13`
- 证据：
  - `### 模式 1: PR URL`
  - `### 模式 2: 三元组`
- 问题说明：输入协议给出两种入口，但未明确默认优先路径，增加调用方选择成本。
- 修改建议（before/after）：
  - before：并列给出模式 1/模式 2。
  - after：标注默认项（如“默认：模式 1（PR URL）”），并说明模式 2 的适用条件。

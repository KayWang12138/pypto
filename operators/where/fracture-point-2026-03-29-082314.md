## 致命断裂点 (P0)

### FP-1: pypto-op-develop 模板生成的 where_scalar_kernel 参数顺序错误

**类型**: A2 (API/框架问题)

**优先级**: P0 (致命)

**问题描述**:

在 Stage 5 代码生成过程中， `pypto-op-develop` skill 的模板生成的 `where_scalar_kernel` 函数存在参数顺序问题。 根据 PyPTO 约束， 非张量参数（如 `pypto.Element`）必须放在所有张量参数之后, 但模板生成代码时将 `y_scalar` 参数放在了 `output` 之后.

**触发信号**:
- 运行时错误: `Non-tensor parameters must come after all tensor parameters. Found tensor parameter 'output' after non-tensor parameter(s).`

**证据片段**:

```
[RUNTIME_ERROR] where::test_where_level2: Non-tensor parameters must come after all tensor parameters. Found tensor parameter 'output' after non-tensor parameter(s).
```

**根因分析**:

| 维度 | 判断 | 说明 |
|------|------|------|
| 框架 | 是 | PyPTO 明确要求非张量参数放在张量参数之后 |
| Skill | 是 | `pypto-op-develop` 的模板未正确处理参数顺序 |

**Issue 建议**:

**标题**: [PyPTO][API] pypto.frontend.jit kernel 参数顺序约束检查不充分

**类型**: Bug Report

**描述**:

在 `pypto-op-develop` skill 的模板中， 当生成带有 `pypto.Element` 类型参数的 kernel 函数时, 参数顺序不正确. 需要在模板中添加参数排序检查, 确保 `pypto.Element` 等非张量参数放在所有 `pypto.Tensor` 参数之后.

**优化建议**:

1. 修改 `references/impl-template.py` 模板, 添加注释说明参数顺序约束
2. 在代码生成逻辑中, 自动对参数进行排序: Tensor 参数在前, Element/标量参数在后
3. 添加参数顺序校验逻辑

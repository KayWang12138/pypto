```
Agent 输出:

    - adaptive_avg_pool2d 的特殊场景和需额外关注

```

Agent 输出内容混乱，包含重复的 `sys.exit(1)` 片段和无效的代码块。

1. 检查 pypto-op-orchestrator Agent 的 prompt 配置，确保输出格式正确

3. 在 Orchestrator 内部增加输出格式验证

## 5. 实体级断裂点详情

### 5.1 [FP-001] D6-示例代码无法运行: impl-template.py

- **类型**: D6-示例代码无法运行
- **优先级**: 高
- **根因归属**: 文档
- **Issue 类型**: Documentation
- **建议 Issue 标题**: `[Doc] impl-template.py 动态轴声明方式与实际实现不一致`
- **置信度**: high
- **可能关联**: 无

#### 问题描述

`pypto-op-develop/references/impl-template.py` 模板中展示的动态轴声明方式使用 `pypto.SymbolicScalar`，但实际需要使用 `pypto.frontend.dynamic()` 来声明动态轴。这导致按照模板编写的代码首次运行时输出全为 0。

模板示例:
```python
# 模板中未展示动态轴的正确声明方式
```

实际需要的声明方式（参考 avg_pool2d）:
```python
batch_size = pypto.frontend.dynamic("batch_size")
channels = pypto.frontend.dynamic("channels")
```

#### 证据片段

```
测试失败输出:
  Input shape : torch.Size([2, 4, 8, 8])
  Output shape: torch.Size([2, 4, 4, 4])
  Max diff    : 1.115813e+00  # 输出值接近 0，与期望值差异巨大

  ✗ FAIL:
  Not equal to tolerance rtol=0.001, atol=0.001
  Mismatched elements: 127 / 128 (99.2%)
```

#### 复现步骤

1. 使用 pypto-op-develop skill 生成算子实现
2. 按照 impl-template.py 模板的隐含方式使用 `pypto.SymbolicScalar` 传递动态轴
3. 运行测试，观察输出值接近 0

#### 期望行为

impl-template.py 应明确展示动态轴的正确声明方式：
```python
# 在 kernel 函数外部声明动态轴
batch_size = pypto.frontend.dynamic("batch_size")
channels = pypto.frontend.dynamic("channels")

@pypto.frontend.jit(...)
def kernel(
    input: pypto.Tensor((batch_size, channels, H, W), pypto.DT_FP32),
    ...
):
    ...
```

#### 实际行为

impl-template.py 模板未展示动态轴声明，导致开发者可能使用错误的方式（如直接使用 `pypto.SymbolicScalar` 作为参数传递）。

#### 相关链接

- 模板文件: `.claude/skills/pypto-op-develop/references/impl-template.py`
- 参考实现: `models/experimental/vector/AvgPool2d/avg_pool2d.py`

#### 优化建议

1. 更新 `impl-template.py`，添加动态轴声明的示例代码
2. 在 `execution-constraints.md` 中明确说明动态轴声明的正确位置（kernel 函数外部）
3. 在 skill 文档中增加"动态轴声明"章节，对比错误用法和正确用法

### 5.1 [FP-001] A3-参数限制: pypto tensor slicing

- **类型**: A3-参数限制
- **优先级**: 致命
- **根因归属**: 框架
- **Issue 类型**: Feature Request
- **建议 Issue 标题**: `pypto tensor 切片不支持 stride 参数，导致 dilation 操作无法实现`
- **置信度**: 高
- **可能关联**: 无

#### 问题描述

在实现 max_pool2d 算子时，需要支持 dilation（空洞池化）功能。按照标准实现方式，需要使用带 stride 的切片来提取窗口：

```python
input_h_window = input_cur[:, h_start_clamped:h_end_clamped:d_h, :]
```

但 PyPTO 编译时报错：

```
pypto.frontend.parser.error.RenderedParserError: ValueError: step must be 1 or None
```

这表明 PyPTO tensor 切片不支持 stride 参数，导致所有需要 dilation 的算子都无法直接实现。

#### 证据片段

```
File "/workspace/code/pypto/operators/max_pool2d/max_pool2d_impl.py", line 321, in max_pool2d_wrapper
    kernel(x_4d if input_dim == 4 else x.unsqueeze(0), output if input_dim == 4 else output.unsqueeze(0))
...
pypto.frontend.parser.error.RenderedParserError: ValueError: step must be 1 or None
[ERROR] 2026-03-29-04:41:01 (PID:1303524, Device:5, RankID:-1) ERR99999 UNKNOWN applicaiton exception
```

#### 复现步骤

1. 创建一个使用 dilation > 1 的 max_pool2d kernel
2. 尝试使用 `tensor[:, start:end:stride, :]` 切片语法
3. 编译时报错 "step must be 1 or None"

#### 期望行为

支持 Python 标准的切片语法，包括 stride 参数：
```python
tensor[start:end:stride]
```

#### 实际行为

只支持 `step=1` 或 `step=None`，不支持其他 stride 值。

#### 相关链接

- PyTorch max_pool2d dilation: https://pytorch.org/docs/stable/generated/torch.nn.functional.max_pool2d.html
- NumPy stride slicing: https://numpy.org/doc/stable/reference/arrays.indexing.html

#### 优化建议

1. **短期**: 在文档中明确说明切片不支持 stride，并给出 dilation 场景的替代实现建议（如使用 gather 或循环逐元素提取）
2. **中期**: 实现 tensor 切片的 stride 支持，使其与 NumPy/PyTorch 行为一致
3. **长期**: 考虑提供专门的 dilation window 提取 API

### 5.2 [FP-002] D2-文档不完整: pypto.pad

- **类型**: D2-文档不完整
- **优先级**: 高
- **根因归属**: 文档
- **Issue 类型**: Documentation
- **建议 Issue 标题**: `pypto.pad 文档应明确说明不支持左/上填充的限制`
- **置信度**: 高
- **可能关联**: 无

#### 问题描述

`pypto.pad` 文档说明了 "当前仅支持右侧和底部填充"，但这个限制的描述不够醒目，且没有明确说明：
1. 为什么有这个限制
2. 如何处理需要左/上填充的场景（如 max_pool2d）
3. 是否有替代方案

这导致开发者在实现需要 padding 的算子时，需要通过试错才能发现这个限制，然后被迫在 kernel 内部实现边界检查。

#### 证据片段

从 `docs/api/operation/pypto-pad.md`:
```
## 约束说明
1. `pad` 参数的长度必须为2或者4。
2. 当前**仅支持多维情况下在右侧（Right）和底部（Bottom）进行填充，或者1维情况下在右侧（Right）填充**。
   即 `pad` 序列中向左和向上的填充量必须为 0（例如格式必须为 `(0, pad_right, 0, pad_bottom)` 或者`(0, pad_right)`）。
```

虽然文档有说明，但：
1. 这个限制没有放在"功能说明"中，而是放在"约束说明"中
2. 没有提供替代实现方案的指导

#### 复现步骤

1. 阅读 pypto.pad 文档
2. 尝试实现需要左/上填充的 max_pool2d
3. 发现限制后，需要在 kernel 内部通过边界检查来处理

#### 期望行为

1. 在"功能说明"中明确指出不支持左/上填充
2. 提供"如何处理需要左/上填充场景"的实现指南
3. 给出参考示例（如 AvgPool2d 如何处理这个限制）

#### 实际行为

文档只在"约束说明"中提到限制，没有提供替代方案指导。

#### 相关链接

- `docs/api/operation/pypto-pad.md`
- `models/experimental/vector/AvgPool2d/avg_pool2d.py` (参考实现)

#### 优化建议

1. 在"功能说明"章节开头添加醒目提示框，说明不支持左/上填充
2. 添加"常见问题"章节，解释如何处理需要左/上填充的场景
3. 提供一个完整的示例，展示在 kernel 内部处理 padding 边界的标准模式

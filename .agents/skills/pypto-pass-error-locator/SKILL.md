# PyPTO Pass 错误诊断与自动修复技能

本技能提供 PyPTO Pass 模块错误的完整诊断和修复能力，从错误原因定位到自动修复验证的端到端解决方案。

## 使用场景

当某业务场景执行失败，需要分析定位某pass异常原因并自动修复该问题时使用此技能。

## 功能概述

- 解析 PyPTO 运行日志，提取错误信息
- 识别错误相关的 Pass 模块
- 分析错误产生的根本原因
- 自动定位问题代码位置
- 应用自动修复策略
- 验证修复结果

## 前置条件

使用此技能前需要满足以下条件：

1. **环境要求**
   - PyPTO 开发环境已正确配置
   - 可访问 PyPTO 源代码目录
   - 具有日志文件读取权限

2. **依赖技能**
   - `pypto-environment-setup`：用于检查环境状态

## 触发机制

当用户输入包含以下关键字时，自动触发此技能：

- **执行xx用例失败，分析并修复pass失败**：根据用例执行日志信息，识别错误是哪个 pass 模块导致的，分析错误产生的可能原因，并尝试自动修复
- **pass报错**：分析Pass执行过程中的错误信息
- **定位pass错误**：定位导致失败的Pass模块及具体原因
- **修复pass问题**：修复Pass模块中的错误
- **诊断pass异常**：诊断Pass模块的异常行为
- **自动修复pass**：自动修复Pass模块中的可修复错误

## 工作流程

### 步骤 1：问题复现

根据用户提供的用例名称或者执行命令，尝试复现用户问题
- 仅提供了用例名称：参考如下执行示例拼接出正确的执行命令
- 提供了完整的执行命令：使用用户提供的命令进行复现

**执行示例**：

1. UT执行命令示例
```bash
python3 build_ci.py -c -f=cpp -u=NBufferMergeTest.TestNBufferMerge
```

2. ST执行命令示例
```bash
python3 build_ci.py -s=python/tests/st/test_adds_onboard.py::test_adds_onboard
```

**验证检查点**：
- [ ] 问题成功复现
- [ ] 获得可复现的执行命令
- [ ] 记录复现时的环境信息

### 步骤 2：获取日志内容

按如下优先级查找日志文件，获取日志内容信息

**日志查找优先级**：
```
1. 从用户指定路径获取日志文件（如有提供）
   ↓
2. 从 `$ASCEND_PROCESS_LOG_PATH/` 目录获取（如果设置）
   ↓
3. 从 `$ASCEND_WORK_PATH/` 目录获取（如果设置且未设置 ASCEND_PROCESS_LOG_PATH）
   ↓
4. 从 `$HOME/ascend/log/` 目录获取（默认，上面都没有设置时从默认目录查找）
```

**日志文件匹配模式**：
- 最新日志文件：按时间戳排序，选择最新的日志文件
- 错误日志：优先查找包含 "ERROR" 的日志文件
- 指定进程日志：如果日志中包含进程ID，查找对应进程的日志

**验证检查点**：
- [ ] 成功定位日志文件
- [ ] 日志文件可读取
- [ ] 日志内容包含错误信息

### 步骤 3：解析日志关键信息

**日志格式示例**：

以如下pass模块打印的日志格式为例，分段解析：
```
[ERROR] PYPTO(638465):2026-03-16 10:02:24.711 [n_buffer_merge.cpp:530][PASS]:[NBufferMerge.Config]:The VEC_NBUFFER_SETTING key -3 is incorrect; Please set keys of VEC_NBUFFER_SETTING between -1 and max hashOrder 0.
```

**解析字段**：

1. 日志级别：[ERROR]
2. 模块名及进程：PYPTO(638465)
3. 日志打印时间：2026-03-16 10:02:24.711
4. 代码位置及行号：[n_buffer_merge.cpp:530]
5. 所属模块类型：[PASS]
6. 具体模块信息：[NBufferMerge.Config] Pass模块名：`NBufferMerge`，Element类型：`Config`
7. 日志内容：The VEC_NBUFFER_SETTING key -3 is incorrect; Please set keys of VEC_NBUFFER_SETTING between -1 and max hashOrder 0.

**多行错误处理**：
- 检查错误信息是否跨越多行
- 合并相关联的错误上下文
- 提取完整的错误堆栈信息

**日志级别处理**：
- ERROR：必须处理的关键错误
- WARNING：可能导致问题的警告信息
- INFO：辅助调试的信息日志

**验证检查点**：
- [ ] 日志级别正确识别
- [ ] 代码位置准确提取
- [ ] Pass模块名称正确解析
- [ ] 错误内容完整提取
- [ ] 时间戳格式正确解析

### 步骤 4：错误原因分析

#### 4.1 分析流程

**分析步骤**：

1. **定位错误代码位置**
   - 错误日志中获取的相关数据：代码行号、文件名
   - 定位错误：所属代码行 -> 所属函数 -> 所属pass模块
   - 分析相关代码理解上下文

2. **初步分析错误类型**
   - 根据错误日志内容分析
   - 结合对应代码上下文逻辑
   - 确定排查方向

3. **综合分析推断原因**
   - 综合分析日志上下文相关信息
   - 结合用例代码及业务逻辑代码
   - 列举可能的错误原因、代码位置、修复建议

#### 4.2 分析维度

错误原因的分析可从以下维度入手：

1. **输入数据问题**
   - Shape 不对齐
   - Dtype 不匹配
   - 数据范围异常
   - 空张量/零维度
   - NaN/Inf 值

2. **API 使用问题**
   - 参数错误
   - 不支持的配置
   - 缺少必需参数
   - 参数冲突
   - 参数顺序错误

3. **环境问题**
   - NPU 设备不可用
   - 内存不足
   - CANN 版本不兼容
   - 驱动问题
   - 权限问题

4. **代码逻辑问题**
   - 算子实现错误
   - 边界条件处理不当
   - 类型转换错误
   - 内存访问越界
   - 并发竞争

5. **Pass 配置问题**
   - Pass 依赖关系错误
   - Pass 执行顺序问题
   - Pass 配置参数错误
   - Pass 版本不兼容

6. **图结构问题**
   - 节点连接错误
   - 边属性异常
   - 图约束违反
   - 循环依赖

7. **内存管理问题**
   - 内存泄漏
   - 重复释放
   - 内存对齐错误
   - Buffer 大小不足

8. **类型系统问题**
   - 类型推导失败
   - 类型转换不支持
   - 泛型约束违反
   - 类型不匹配

各pass模块常见错误及修复建议可参考：[常见错误及修复建议](references/pass-modules-knowledge-base.md)

#### 4.3 分析技巧

1. **错误信息中的处理建议**
   - 错误信息中通常带有处理建议
   - 可根据错误内容推断可能的错误类型和原因

2. **参数配置类错误**
   - 查阅参数文档中的参数约束和作用
   - 判断参数是否合法
   - 参数配置文档通常位于 `docs/api/config` 目录下

3. **算子用法和约束**
   - python用例中涉及的算子
   - 通过文档了解各算子的用法和约束
   - 算子文档通常位于 `docs/api/operation` 目录下

**验证检查点**：
- [ ] 错误类型正确分类
- [ ] 错误原因分析准确
- [ ] 代码位置精确定位
- [ ] 修复建议合理可行

### 步骤 5：问题修复

执行自动修复前，列举出上述步骤分析得到的错误原因及修复建议，让用户确认是否需要自动修复，根据哪条建议进行修复

**修复策略分类**：

1. **可自动修复的问题**
   - 参数配置错误
   - 类型转换错误
   - 数据类型不匹配
   - 简单的语法错误
   - 导入路径错误
   - **处理方式**：直接修复

2. **需人工判断的问题**
   - 算子实现错误
   - 边界条件处理不当
   - 复杂的逻辑错误
   - 性能优化问题
   - **处理方式**：生成修复建议，等待用户确认

3. **需要环境调整的问题**
   - 内存不足
   - NPU 设备问题
   - 权限问题
   - **处理方式**：调用 `pypto-environment-setup` 技能

**修复步骤**：

1. **备份原始代码**
   - 创建修复前的代码备份
   - 记录修改的文件列表

2. **应用修复方案**
   - 根据错误类型选择修复策略
   - 执行相应的修复操作

3. **代码质量检查**
   - 检查修复后的代码是否符合规范
   - 确保没有引入新的问题

**失败处理机制**：

- 如果自动修复失败，回退到原始代码
- 记录失败原因和错误信息
- 提供手动修复建议

**验证检查点**：
- [ ] 修复方案正确选择
- [ ] 代码修改准确执行
- [ ] 备份文件成功创建
- [ ] 代码质量检查通过

### 步骤 6：修复验证

#### 6.1 执行测试

1. **执行相关用例**
   - 根据用户提供的用例，执行命令验证相关用例
   - 检查运行结果是否符合预期
   - 检查日志中是否还有ERROR级别的日志

2. **测试命令示例**
```bash
# UT测试
python3 build_ci.py -c -f=cpp -u=NBufferMergeTest.TestNBufferMerge

# ST测试
python3 build_ci.py -s=python/tests/st/test_adds_onboard.py::test_adds_onboard
```

#### 6.2 回归检查

1. **运行相关测试用例集**
   - 执行相关的回归测试
   - 确保修复未破坏其他功能

2. **回归测试范围**
   - 同一Pass模块的其他测试用例
   - 依赖该Pass模块的测试用例
   - 相关业务场景的测试用例

#### 6.3 失败回滚

1. **测试不通过情况**
   - 如果测试不通过，将修改内容还原
   - 记录回滚原因
   - 分析失败原因，提供新的修复建议

2. **回滚操作**
   - 恢复备份的原始代码
   - 清理临时文件
   - 记录回滚日志

#### 6.4 性能验证（可选）

如果修复涉及性能优化，需要进行性能验证：
- 对比修复前后的性能数据
- 确保性能没有下降
- 记录性能改进情况

**验证检查点**：
- [ ] 测试用例执行成功
- [ ] 运行结果符合预期
- [ ] 日志中无ERROR级别日志
- [ ] 回归测试通过
- [ ] 未引入新的问题
- [ ] 性能验证通过（如适用）

```markdown
2. 具体步骤：

   - 将参数值调整为有效范围（-1 到 0）
   - 重新执行测试用例

### 修复结果
- 修复状态：成功
- 测试结果：通过
- 回归测试：通过
```

## 版本兼容性

本技能支持以下 PyPTO 版本：
- PyPTO 8.5.0+
- 建议使用最新版本以获得最佳支持

不同版本可能存在以下差异：
- 日志格式可能略有不同
- Pass模块名称可能变化
- 错误信息内容可能更新

## 性能优化建议

处理大规模日志文件时：
1. 使用流式读取，避免一次性加载整个文件
2. 优先搜索ERROR级别日志，减少处理范围
3. 使用多线程并行处理多个日志文件
4. 缓存已解析的日志信息，避免重复解析

## 常见问题

### Q1: 日志文件找不到怎么办？
A: 检查环境变量设置，确认日志文件路径。可以使用 `find` 命令搜索日志文件。

### Q2: 错误信息不完整怎么办？
A: 调整日志级别为DEBUG，重新执行测试用例，获取更详细的日志信息。

### Q3: 自动修复失败怎么办？
A: 查看修复失败原因，参考手动修复建议，进行人工修复。

### Q4: 如何确认修复是否有效？
A: 执行相关测试用例，检查运行结果和日志信息，确保无ERROR级别日志。

### Q5: 修复后引入了新问题怎么办？
A: 执行回滚操作，恢复原始代码，分析失败原因，提供新的修复方案。

# PyPTO Pass 错误诊断与修复技能

本技能提供 PyPTO Pass 模块错误的完整诊断和修复能力，从错误原因定位到问题修复验证的端到端解决方案。

## 使用场景

当某业务场景执行失败，需要分析定位某pass抛出异常原因并修复该问题时使用此技能。

## 功能概述

- 解析 PyPTO 运行日志，提取错误信息
- 识别错误相关的 Pass 模块
- 分析错误产生的根本原因
- 定位问题代码位置
- 提供修复方案并等待用户确认
- 执行用户确认的修复操作
- 验证修复结果

## 前置条件

使用此技能前需要满足以下条件：

1. **环境要求**
   - PyPTO 开发环境已正确配置
   - 可访问 PyPTO 源代码目录
   - 具有日志文件读取权限

2. **依赖技能**
   - `pypto-environment-setup`：用于检查环境状态

## 触发机制

当用户输入包含以下关键字时，自动触发此技能：

- **执行xx用例失败，分析并修复pass失败**：定位导致失败的Pass模块及具体原因，并提供修复方案
- **pass报错**：分析Pass执行过程中的错误信息
- **定位pass错误**：定位导致失败的Pass模块及具体原因
- **诊断pass异常**：诊断Pass模块的异常行为

## 工作流程

### 步骤 1：问题复现

根据用户提供的用例名称或者执行命令，尝试复现用户问题
- 仅提供了用例名称：参考如下执行示例拼接出正确的执行命令
- 提供了完整的执行命令：使用用户提供的命令进行复现

**执行示例**：

1. UT执行命令示例
```bash
python3 build_ci.py -c -f=cpp -u=NBufferMergeTest.TestNBufferMerge
```

2. ST执行命令示例
```bash
python3 build_ci.py -s=python/tests/st/test_adds_onboard.py::test_adds_onboard
```

**验证检查点**：
- [ ] 问题成功复现
- [ ] 获得可复现的执行命令
- [ ] 记录复现时的环境信息

### 步骤 2：获取日志内容

按如下优先级查找日志文件，获取日志内容信息

**日志查找优先级**：
```
1. 从用户指定路径获取日志文件（如有提供）
   ↓
2. 从 `$ASCEND_PROCESS_LOG_PATH/` 目录获取（如果设置了该环境变量）
   ↓
3. 从 `$ASCEND_WORK_PATH/` 目录获取（如果设置且未设置 ASCEND_PROCESS_LOG_PATH）
   ↓
4. 从 `$HOME/ascend/log/` 目录获取（默认，上面都没有设置时从默认目录查找）
```

**日志文件匹配模式**：
- 最新日志文件：按时间戳排序，选择最新的日志文件
- 错误日志：优先查找包含 "ERROR" 的日志文件
- 指定进程日志：如果日志中包含进程ID，查找对应进程的日志

**验证检查点**：
- [ ] 成功定位日志文件
- [ ] 日志文件可读取
- [ ] 日志内容包含错误信息

### 步骤 3：解析日志关键信息

**日志格式示例**：

以如下pass模块打印的日志格式为例，分段解析：
```
[ERROR] PYPTO(638465):2026-03-16 10:02:24.711 [n_buffer_merge.cpp:530][PASS]:[NBufferMerge.Config]:The VEC_NBUFFER_SETTING key -3 is incorrect; Please set keys of VEC_NBUFFER_SETTING between -1 and max hashOrder 0.
```

**解析字段**：

1. 日志级别：[ERROR]
2. 模块名及进程：PYPTO(638465)
3. 日志打印时间：2026-03-16 10:02:24.711
4. 代码位置及行号：[n_buffer_merge.cpp:530]
5. 所属模块类型：[PASS]
6. 具体模块信息：[NBufferMerge.Config] Pass模块名：`NBufferMerge`，Element类型：`Config`
7. 日志内容：The VEC_NBUFFER_SETTING key -3 is incorrect; Please set keys of VEC_NBUFFER_SETTING between -1 and max hashOrder 0.

**多行错误处理**：
- 检查错误信息是否跨越多行
- 合并相关联的错误上下文
- 提取完整的错误堆栈信息

**日志级别处理**：
- ERROR：必须处理的关键错误
- WARNING：可能导致问题的警告信息
- INFO：辅助调试的信息日志

**验证检查点**：
- [ ] 日志级别正确识别
- [ ] 代码位置准确提取
- [ ] Pass模块名称正确解析
- [ ] 错误内容完整提取
- [ ] 时间戳格式正确解析

### 步骤 4：错误原因分析

#### 4.1 分析流程

**分析步骤**：

1. **定位错误代码位置**
   - 错误日志中获取的相关数据：代码行号、文件名
   - 定位错误：所属代码行 -> 所属函数 -> 所属pass模块
   - 分析相关代码理解上下文

2. **初步分析错误类型**
   - 根据错误日志内容分析
   - 结合对应代码上下文逻辑
   - 确定排查方向

3. **综合分析推断原因**
   - 综合分析日志上下文相关信息
   - 结合用例代码及业务逻辑代码
   - 列举可能的错误原因、代码位置、修复建议

#### 4.2 分析维度

错误原因的分析可从以下维度入手：

1. **输入数据问题**
   - Shape 不对齐
   - Dtype 不匹配
   - 数据范围异常
   - 空张量/零维度
   - NaN/Inf 值

2. **API 使用问题**
   - 参数错误
   - 不支持的配置
   - 缺少必需参数
   - 参数冲突
   - 参数顺序错误

3. **环境问题**
   - NPU 设备不可用
   - 内存不足
   - CANN 版本不兼容
   - 驱动问题
   - 权限问题

4. **代码逻辑问题**
   - 算子实现错误
   - 边界条件处理不当
   - 类型转换错误
   - 内存访问越界
   - 并发竞争

5. **Pass 配置问题**
   - Pass 依赖关系错误
   - Pass 执行顺序问题
   - Pass 配置参数错误
   - Pass 版本不兼容

6. **图结构问题**
   - 节点连接错误
   - 边属性异常
   - 图约束违反
   - 循环依赖

7. **内存管理问题**
   - 内存泄漏
   - 重复释放
   - 内存对齐错误
   - Buffer 大小不足

8. **类型系统问题**
   - 类型推导失败
   - 类型转换不支持
   - 泛型约束违反
   - 类型不匹配

5. **精度问题**
   - 无执行异常，但计算结果与预期不符

#### 4.3 分析技巧

1. **错误信息中的处理建议**
   - 错误信息中通常带有处理建议
   - 可根据错误内容推断可能的错误类型和原因

2. **参数配置类错误**
   - 查阅参数文档中的参数约束和作用
   - 判断参数是否合法
   - 参数配置文档通常位于 `docs/api/config` 目录下

3. **算子用法和约束**
   - python用例中涉及的算子
   - 通过文档了解各算子的用法和约束
   - 算子文档通常位于 `docs/api/operation` 目录下

**验证检查点**：
- [ ] 错误类型正确分类
- [ ] 错误原因分析准确
- [ ] 代码位置精确定位
- [ ] 修复建议合理可行

### 步骤 5：问题修复

根据步骤4分析得到的错误原因及修复建议，向用户展示所有可能的修复方案，等待用户确认后再执行修复操作。

**修复原则**：

- 所有修复操作都必须经过用户确认
- 列举所有可行的修复方案，供用户选择
- 明确说明每个修复方案的风险和影响
- 修复前必须备份原始代码

**修复方案类型**：

1. **参数配置错误**
   - 配置参数超出有效范围
   - 配置键值使用错误
   - **修复方式**：对比类似用例，分析配置差异，修正用例配置

2. **代码逻辑错误**
   - 算子实现错误
   - 边界条件处理不当
   - 类型转换错误
   - 内存访问越界
   - 并发竞争
   - **修复方式**：定位问题代码，修改逻辑实现

3. **环境问题**
   - 内存不足
   - NPU 设备问题
   - 权限问题
   - CANN 版本不兼容
   - **修复方式**：调用 `pypto-environment-setup` 技能或提供环境调整建议

4. **API 使用问题**
   - 参数错误
   - 不支持的配置
   - 缺少必需参数
   - 参数冲突
   - **修复方式**：查阅API文档，修正参数使用

5. **精度问题**
   - 无执行异常，但计算结果与预期不符
   - **修复方式**：调用 `pypto-binary-search-verify` 技能进行分析

**修复步骤**：

1. **展示修复方案**
   - 列举所有可行的修复方案
   - 说明每个方案的优缺点
   - 标注推荐方案（如有）

2. **等待用户确认**
   - 使用 question 工具让用户选择修复方案
   - 用户可选择确认修复、跳过修复或提供新的方案

3. **备份原始代码**
   - 创建修复前的代码备份
   - 记录修改的文件列表

4. **执行修复操作**
   - 根据用户确认的方案执行修复
   - 最小化修改，不调整无关代码格式
   - 记录修改的详细内容

5. **代码质量检查**
   - 检查修复后的代码是否符合规范
   - 确保没有引入新的问题

**失败处理机制**：

- 如果修复失败，自动回退到原始代码
- 记录失败原因和错误信息
- 提供其他修复方案供用户选择

**验证检查点**：
- [ ] 修复方案已展示给用户
- [ ] 用户已确认修复方案
- [ ] 备份文件成功创建
- [ ] 代码修改准确执行
- [ ] 代码质量检查通过

### 步骤 6：修复验证

#### 6.1 执行测试

1. **执行相关用例**
   - 根据用户提供的用例，执行命令验证相关用例
   - 检查运行结果是否符合预期
   - 检查日志中是否还有ERROR级别的日志

   - 执行相关的回归测试
   - 确保修复未破坏其他功能

2. **回归测试范围**
   - 同一Pass模块的其他测试用例
   - 依赖该Pass模块的测试用例
   - 相关业务场景的测试用例

#### 6.3 失败回滚

1. **测试不通过情况**
   - 如果测试不通过，将修改内容还原
   - 记录回滚原因

2. **回滚操作**
   - 恢复备份的原始代码

#### 6.4 性能验证（可选）

如果修复涉及性能优化，需要进行性能验证：

- [ ] 回归测试通过

- [ ] 性能验证通过（如适用）

- 回归测试：通过

## 版本兼容性

本技能支持以下 PyPTO 版本：
- PyPTO 8.5.0+
- 建议使用最新版本以获得最佳支持

不同版本可能存在以下差异：
- 日志格式可能略有不同
- Pass模块名称可能变化
- 错误信息内容可能更新

## 性能优化建议

处理大规模日志文件时：
1. 使用流式读取，避免一次性加载整个文件
2. 优先搜索ERROR级别日志，减少处理范围
3. 使用多线程并行处理多个日志文件
4. 缓存已解析的日志信息，避免重复解析

# 阶段一：需求理解详细指南

**以下内容可与PyPTO下的skill pypto-intent-understanding结合使用，以本文件为主**

## 1. 阅读Ascend C算子README

提取以下信息：
- 标题、功能描述
- 数学公式
- 输入输出参数规格（包括**可选参数**）
- 支持的数据类型
- 典型配置

## 2. 阅读Ascend C算子实现代码 ⭐⭐⭐

**关键：不要只看README，必须查看实际实现代码！**

### 2.1 必须查看的文件

1. **op_api/*.h 或 docs/*.md** - 函数签名，包含所有参数声明
2. **host/tiling/*.cpp** - tiling策略，了解实际计算流程
3. **kernel/**/*.cpp / kernel/**/*.h** - 核心计算逻辑，条件分支处理

### 2.2 复杂形状分析 ⭐

**如果README中的形状描述不够清晰，必须查看AscendC代码具体实现！**

### 2.3 重点关注内容

- **可选参数的实际使用位置**和条件判断
- **条件分支逻辑**（哪些参数组合是有效的）
- **实际支持的数据类型**（可能与README有差异）
- **分块计算策略**（是否使用Flash Attention等优化）
- **性能关键路径**

## 3. 提炼实际功能需求 ⭐⭐⭐

**这是最重要的步骤！**

### 步骤1：创建功能对比表

对比README描述与实际代码实现，明确功能范围：

```
| 功能模块 | README描述 | 实际代码支持 | PyPTO实现优先级 |
|---------|-----------|-------------|----------------|
| 核心计算 | 必需参数A, B | ✓ 完整实现 | P0 必须实现 |
| 扩展功能1 | 可选参数C | ✓ 有条件实现 | P1 必须实现 |
| 扩展功能2 | 可选参数D | ✗ 未实现或有限制 | P2 可能需要简化 |
```

### 步骤2：分析可选参数的实际意义

**分析方法**：

1. **定位代码位置**：在kernel代码中搜索参数名，找到使用位置
2. **理解计算逻辑**：分析参数如何影响计算流程
3. **评估实现复杂度**：判断PyPTO API是否支持，实现难度如何
4. **查看AscendC实现**：如果不确定，直接看AscendC代码怎么处理的

**分析维度**：

| 维度 | 说明 | 示例 |
|-----|------|------|
| 代码位置 | 参数在计算流程的哪个阶段使用 | 输入预处理/核心计算/输出后处理 |
| 计算逻辑 | 参数如何影响计算 | 条件分支/数值缩放/数据选择 |
| 实现复杂度 | PyPTO是否支持 | 低(直接支持)/中(需要特殊处理)/高(不支持) |
| 依赖关系 | 是否依赖其他参数 | 独立/依赖参数X/与参数Y互斥 |

### 步骤3：确定实现优先级

**重要原则**：
- **P0和P1功能必须在第一个版本实现**
- 只有P2/P3功能可以延后

**优先级定义**：
- **P0（必须）**：核心功能，没有就无法工作，所有场景都需要
- **P1（重要）**：常用功能，影响大多数使用场景，**必须在第一个版本实现**
- **P2（可选）**：特殊场景功能，根据需求决定是否实现
- **P3（暂缓）**：PyPTO不支持或实现成本过高，暂不实现

### 步骤4：记录技术限制

**分析框架**：

```
技术限制分析：

1. 功能A的限制
   - 问题：[描述具体的实现障碍]
   - 影响：[说明对功能的影响范围]
   - 原因：[PyPTO API限制/算法特性/其他]
   - 解决方案：[替代方案或后续计划]

2. 功能B的限制
   - 问题：
   - 影响：
   - 原因：
   - 解决方案：
```

## 4. 生成spec.md

根据以上分析创建 `spec.md`：

```markdown
## 算子需求规范

### 1. 基础信息
- **算子名称**: xxx
- **数学公式**: ...

### 2. 输入输出规格
| 变量 | Shape | Dtype | 说明 | PyPTO实现状态 |
|-----|-------|-------|------|--------------|
| 输入A | [...] | DT | 核心输入 | ✓ P0 |
| 输入B(可选) | [...] | DT | 扩展功能 | ✓ P1 |
| 输入C(可选) | [...] | DT | 特殊场景 | ⚠️ P2 有限制 |

### 3. 实现状态说明
[说明哪些功能已实现，哪些暂不支持及原因]
```

## 5. 输出需求理解报告

```
custom/{算子名}/
├── spec.md                          # 需求规格
└── REQUIREMENT_ANALYSIS.md          # 需求分析报告（可选，复杂算子建议）
```

## 6. 重要提醒 ⭐⭐⭐

1. **不要猜测**：如果不确定某个功能的实现方式，直接去看AscendC代码
2. **完整分析**：P0和P1功能必须完整分析，不能遗漏
3. **第一版完整**：第一个PyPTO版本必须包含P0和P1功能

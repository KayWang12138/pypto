# PyPTO 算子性能调优编排器

## 角色

你是性能调优流程控制器（orchestrator）。你的唯一职责是确保调优流程按照固定顺序严格执行、迭代轮次完整执行、Todo 清单实时更新。

你不负责具体的优化建议或代码修改，只负责：
1. 控制流程推进
2. 校验每一步的完成条件
3. 强制维护 Todo 清单
4. 阻止跳跃执行
5. 控制迭代轮次的完整执行

⛔ 你必须在整个调优过程中保持加载，直到 S5_REPORT 完成为止。

---

## 三级状态机

调优流程是一个严格的三级状态机，只有一个方向，禁止回退或跳跃。

### 第一级：主流程状态机

```
INIT → S1_SETUP → S2_COLLECT → S3_ANALYZE → S4_TUNE → S5_REPORT → DONE
```

### 第二级：S4_TUNE 子阶段状态机

```
S4_TUNE = PHASE_FRONTEND → PHASE_SWIMLANE → PHASE_INCORE
```

### 第三级：每个 PHASE 内部的迭代循环

```
每个 PHASE 内部反复执行以下循环，直到退出条件满足：

┌──────────────────────────────────────────────────────────┐
│  ITER_START（选择优化点）                                  │
│      │                                                   │
│      ▼                                                   │
│  ITER_MODIFY（修改代码，单参数）                            │
│      │                                                   │
│      ▼                                                   │
│  ITER_VERIFY（验证精度）                                   │
│      │                                                   │
│      ├─ 精度失败 → ITER_ROLLBACK（回退代码）               │
│      │                   │                                │
│      │                   ▼                                │
│      │               ITER_RECORD（记录失败）               │
│      │                   │                                │
│      ├───────────────────┘                                │
│      │                                                   │
│      ▼ （精度通过）                                        │
│  ITER_MEASURE（测试性能）                                  │
│      │                                                   │
│      ├─ 性能回退 → ITER_ROLLBACK → ITER_RECORD            │
│      │                                                   │
│      ▼ （性能提升或持平）                                   │
│  ITER_RECORD（记录结果，更新Todo）                          │
│      │                                                   │
│      ▼                                                   │
│  ITER_JUDGE（判断退出条件）                                │
│      │                                                   │
│      ├─ 未达标且轮次未耗尽 → 回到 ITER_START               │
│      │                                                   │
│      └─ 达标或轮次耗尽 → PHASE_SUMMARY（生成交接摘要）      │
└──────────────────────────────────────────────────────────┘
```

## 全状态定义与转移条件

### 第一级状态转移表

| 当前状态 | 完成条件 | 转移到 | 强制动作 |
|---------|---------|--------|---------|
| INIT | 用户确认目标性能值 | S1_SETUP | 记录目标到 Todo |
| S1_SETUP | 环境OK + 精度通过 | S2_COLLECT | ⛔ 强制创建完整 Todo |
| S2_COLLECT | swimlane.json 存在 | S3_ANALYZE | 无 |
| S3_ANALYZE | 性能报告文件存在 | S4_TUNE | 记录基准性能 |
| S4_TUNE | 3个PHASE全部完成 | S5_REPORT | ⛔ 各PHASE间强制交接 |
| S5_REPORT | 报告文件已保存 | DONE | ⛔ 还原 debug_options |

### 第二级状态转移表（S4_TUNE 内部）

| 当前 PHASE | 进入动作 | 退出条件 | 转移到 |
|-----------|---------|---------|--------|
| PHASE_FRONTEND | 加载 tune-frontend 子技能 | 达标 或 连续5轮无提升 | ⛔ 生成摘要 → ⛔ 执行 /compact → PHASE_SWIMLANE |
| PHASE_SWIMLANE | 加载 tune-swimlane 子技能 | 达标 或 连续8轮无提升 | ⛔ 生成摘要 → ⛔ 执行 /compact → PHASE_INCORE |
| PHASE_INCORE | 加载 tune-incore 子技能 | 达标 或 达到理论上限 | ⛔ 生成摘要 → S5_REPORT |

### 第三级状态转移表（迭代轮次内部）

⛔ 这是调优过程中最核心的控制，每一步都是独立操作，必须逐步执行。

| 迭代子状态 | 执行内容 | 完成标志 | 转移到 | 失败处理 |
|-----------|---------|---------|--------|---------|
| ITER_START | 根据子技能指南选择一个优化点 | 确定了要改什么参数 | ITER_MODIFY | 无优化点可选 → PHASE_SUMMARY |
| ITER_MODIFY | 修改代码，只改一个参数 | 代码已修改 | ITER_VERIFY | - |
| ITER_VERIFY | 运行测试用例验证精度 | 输出含 "passed" | ITER_MEASURE | → ITER_ROLLBACK |
| ITER_MEASURE | 运行用例采集性能数据 | 新的性能数据已获取 | ITER_RECORD | → ITER_ROLLBACK |
| ITER_RECORD | 更新 Todo 性能记录表 | Todo 已更新 | ITER_JUDGE | - |
| ITER_JUDGE | 检查退出条件 | 判定结果 | ITER_START 或 PHASE_SUMMARY | - |
| ITER_ROLLBACK | 回退代码修改 | 代码已恢复 | ITER_RECORD | - |

## ⛔ 每次回复前的强制自检

在生成任何回复之前，你必须完成以下自检。如果任何一项未通过，必须先处理该项，禁止继续执行其他操作。

```
□ Q1: 当前处于哪个状态？
      第一级: [INIT / S1 / S2 / S3 / S4 / S5 / DONE]
      第二级: [FRONTEND / SWIMLANE / INCORE]（仅 S4 时）
      第三级: [START / MODIFY / VERIFY / MEASURE / RECORD / JUDGE / ROLLBACK]
              （仅 S4 时）

□ Q2: 当前子状态的完成条件是否满足？
      → 不满足 → 继续执行当前子状态，禁止推进

□ Q3: 本轮回复是否只推进了一个子状态？
      → ITER_START → ITER_MODIFY  ✅（一个）
      → ITER_START → ITER_MODIFY → ITER_VERIFY  ❌（三个，太多了）

□ Q4: 强制动作是否已完成？
       → S1→S2: Todo 已创建？
       → PHASE 间: 交接摘要已生成 **且 /compact 已执行**？
       → S5→DONE: debug_options 已还原？

□ Q5: Todo 是否最新？
      → 刚完成了一步 → 是否已更新？
```

## 迭代轮次执行规范

### ⛔ 单次回复执行边界

每次回复最多执行 **1-2 个相邻子状态**，具体规则：

```
允许的回复粒度（紧耦合的组合允许合并）：

✅ ITER_START + ITER_MODIFY
   → 选优化点 + 改代码（必须知道改什么才能改）

✅ ITER_VERIFY（单独执行，需要等待命令执行结果）

✅ ITER_MEASURE（单独执行，需要等待性能数据）

✅ ITER_RECORD + ITER_JUDGE（记录 + 判断，紧耦合）

✅ ITER_ROLLBACK + ITER_RECORD（回退 + 记录失败，紧耦合）

禁止的回复粒度：

❌ ITER_START → ITER_MODIFY → ITER_VERIFY → ITER_MEASURE
   （一次回复跨越4步，信息量过大无法校验）

❌ 跳过 ITER_VERIFY 直接 ITER_MEASURE
   （精度都没验就测性能）

❌ 跳过 ITER_RECORD 直接下一轮 ITER_START
   （没有记录就继续，Todo 会过时）
```

### ⛔ 单参数原则

```
ITER_MODIFY 阶段，每次只允许修改一个优化参数：

✅ 只改 BLOCK_SIZE: 128 → 64
✅ 只改 TileShape: (1,1,128) → (1,1,256)
✅ 只加一个 runtime_options 参数

❌ 同时改 BLOCK_SIZE + TileShape
❌ 同时改 unroll_list + stitch_max_num
❌ 同时加两个新参数
```

### 迭代轮次编号规则

```
轮次编号格式: {PHASE前缀}-{N}
示例:
  F-1: 开箱调优第1轮
  F-2: 开箱调优第2轮
  S-1: 深度调优第1轮
  S-2: 深度调优第2轮
  I-1: 核内调优第1轮
  I-2: 核内调优第2轮
```

## 退出条件详细定义

### 各 PHASE 的退出条件

**PHASE_FRONTEND 退出条件（满足任一）**：

| 条件 | 判定方法 | 动作 |
|------|---------|------|
| 性能达标 | 当前执行时间 ≤ 目标值 | → 生成摘要 → PHASE_SWIMLANE |
| 连续5轮无提升 | 最近5轮的执行时间都 ≥ 当前最佳 | → 生成摘要 → PHASE_SWIMLANE |
| 用户要求停止 | 用户明确说停止 | → 生成摘要 → S5_REPORT |
| 无优化点可选 | 子技能指南中的优化项全部尝试过 | → 生成摘要 → PHASE_SWIMLANE |

**PHASE_SWIMLANE 退出条件（满足任一）**：

| 条件 | 判定方法 | 动作 |
|------|---------|------|
| 性能达标 | 当前执行时间 ≤ 目标值 | → 生成摘要 → PHASE_INCORE |
| 连续8轮无提升 | 最近8轮的执行时间都 ≥ 当前最佳 | → 生成摘要 → PHASE_INCORE |
| 用户要求停止 | 用户明确说停止 | → 生成摘要 → S5_REPORT |

**PHASE_INCORE 退出条件（满足任一）**：

| 条件 | 判定方法 | 动作 |
|------|---------|------|
| 性能达标 | 当前执行时间 ≤ 目标值 | → 生成摘要 → S5_REPORT |
| 达到理论性能上限 | 核心利用率 > 80% 且 气泡率 < 10% | → 生成摘要 → S5_REPORT |
| 用户要求停止 | 用户明确说停止 | → 生成摘要 → S5_REPORT |

### ITER_JUDGE 判定流程

```
ITER_JUDGE 执行时，按以下顺序判断：

1. 性能是否达标？
   当前执行时间 ≤ 目标值
   → 是: 输出"达标"，转移至 PHASE_SUMMARY
   → 否: 继续

2. 当前轮次是否有提升？
   当前执行时间 < 上一轮执行时间
   → 是: 重置连续无提升计数器为 0
   → 否: 连续无提升计数器 +1

3. 连续无提升次数是否达到阈值？
   FRONTEND: 5次, SWIMLANE: 8次
   → 是: 输出"阶段内优化耗尽"，转移至 PHASE_SUMMARY
   → 否: 继续

4. 是否达到状态看板输出时机？
   总轮次 % 5 == 0
   → 是: 输出状态看板

5. 继续下一轮
   → 转移至 ITER_START
```

## 完成条件校验方法

每个状态的完成条件必须通过实际命令或文件检查验证，禁止凭记忆或假设判断。

### S1_SETUP

```bash
npu-smi info                          # 必须有 NPU 设备输出
ls $PTO_TILE_LIB_CODE_PATH/include/pto/  # 路径必须存在
```

精度校验：
```
必须检查：
1. 命令是否正常退出（无 timeout、无 segfault）
2. 输出中是否包含 "passed" 或 "success"
3. 不包含 "failed" 或 "error" 或 "timeout"

⛔ 如果失败：
- 不修复，换卡尝试（最多 3 次）
- 仍然失败 → 停止，告知用户
```

### S2_COLLECT

```bash
ls output/output_*/merged_swimlane.json   # 必须存在
```

### S3_ANALYZE

```bash
ls output/output_*/performance_analysis_report.md   # 必须存在
```

### S4_TUNE 各 PHASE

```
退出条件（满足任一）：
1. 执行时间 ≤ 目标值
2. 连续 N 次优化无提升（FRONTEND: 5次, SWIMLANE: 8次）
3. 用户要求停止
```

### S5_REPORT

```
报告文件已保存到算子目录下
debug_options 已还原（runtime_debug_mode 移除或置 0）
```

## 防跳跃规则

### 规则 1：单步推进

```
每次回复只做一件事：
✅ "执行精度校验" → 完成 → 更新 Todo → 结束本轮回复
❌ "执行精度校验" + "采集性能数据" + "开始分析"
```

### 规则 2：禁止跨阶段加载子技能

```
当前状态: PHASE_FRONTEND
✅ 只能加载: tune-frontend/SKILL.md
❌ 禁止加载: tune-swimlane/SKILL.md, tune-incore/SKILL.md

当前状态: PHASE_SWIMLANE
✅ 只能加载: tune-swimlane/SKILL.md
❌ 禁止加载: tune-incore/SKILL.md（除非 PHASE_SWIMLANE 已完成）
```

### 规则 3：单参数修改

```
ITER_MODIFY 阶段：
✅ 只改 BLOCK_SIZE → 验证精度 → 测性能 → 记录
❌ 同时改 BLOCK_SIZE + TileShape → 测性能
```

## 异常处理

### S1_SETUP 精度失败

```
1. 换卡尝试（最多 3 次）
2. 仍然失败 → 停止，不修复，告知用户
3. 状态机停留在 S1_SETUP，等待用户决策
```

### 迭代轮次精度失败（ITER_VERIFY）

```
1. 不要立即回退，先做简单分析
   - 是否只改了一个参数？（应该只改了一个）
   - 修改的参数值是否在合理范围内？
   - 错误信息是什么？

2. 如果能快速定位原因 → 尝试修正参数值 → 重新 ITER_VERIFY
   ⚠️ 最多尝试 1 次修正

3. 如果无法快速定位 → ITER_ROLLBACK
   - 回退代码修改
   - ITER_RECORD 记录失败（标记 ❌）
   - ITER_JUDGE 判断是否继续

⛔ 禁止：
- 花大量时间修复精度问题（精度问题是实现问题，不是调优问题）
- 修正次数超过 1 次
- 不回退就继续下一个优化点
```

### 迭代轮次性能回退（ITER_MEASURE）

```
1. 记录性能回退幅度
2. ITER_ROLLBACK 回退修改
3. ITER_RECORD 记录失败（标记 ❌回退）
4. ITER_JUDGE 判断是否继续
```

### 执行超时

```
任何命令超过 300 秒：
1. 标记当前操作失败
2. ITER_ROLLBACK 回退修改（如果有）
3. ITER_RECORD 记录超时
4. ITER_JUDGE 判断是否继续
```

### 长期无法达标

```
如果所有 3 个 PHASE 都完成了但仍未达标：
```

## 1. 概述

PyPTO运行时机制负责管理编译后代码的执行，主要包括四个核心机制：

### 1.1 机制分类

| 机制 | 职责 | 关键组件 |
|------|------|---------|
| **执行调度** | MPMD执行调度系统 | DeviceAgent、HostAgent、TaskQueue |
| **内存管理** | 内存分配、重用、优化 | 内存分配器、内存层级管理 |
| **同步机制** | 多核并行执行同步 | Barrier、Sync、Wait |
| **Launcher机制** | 任务启动和执行 | DeviceLauncher、EmulationLauncher |

### 1.2 运行时流程

```
编译后的Function
    ↓
执行调度机制
    ├─→ 任务分解
    ├─→ 资源分配
    └─→ 依赖管理
    ↓
Launcher机制
    ├─→ 选择启动器
    └─→ 启动任务
    ↓
内存管理机制
    ├─→ 内存分配
    └─→ 内存重用
    ↓
同步机制
    ├─→ 同步点
    └─→ 数据一致性
    ↓
执行完成
```

## 2. 执行调度机制

### 2.1 定义与作用

**定义**：MPMD（Multiple Program Multiple Data）执行调度系统，管理任务调度、资源分配和依赖关系。

**作用**：
- 管理任务调度
- 分配计算资源
- 处理任务依赖
- 优化执行顺序

### 2.2 关键组件

#### 2.2.1 DeviceAgent（设备端任务代理）

**定义**：设备端任务的代理，负责设备端任务的调度和执行。

**职责**：
- 接收设备端任务
- 管理设备资源
- 调度任务执行
- 处理任务完成

**代码位置**：
- `framework/src/machine/runtime/`

#### 2.2.2 HostAgent（主机端任务代理）

**定义**：主机端任务的代理，负责主机端任务的调度和执行。

**职责**：
- 接收主机端任务
- 管理主机资源
- 协调设备任务
- 处理同步操作

**代码位置**：
- `framework/src/machine/runtime/`

#### 2.2.3 TaskQueue（任务队列）

**定义**：管理待执行任务的队列。

**职责**：
- 任务入队和出队
- 任务优先级管理
- 任务依赖检查
- 任务状态跟踪

### 2.3 MPMD执行模型

**MPMD（Multiple Program Multiple Data）**：
- **Multiple Program**：多个不同的程序/函数
- **Multiple Data**：不同的数据集合
- **并行执行**：多个程序同时处理不同数据

**执行模式**：
```
程序1 → 数据1 ┐
程序2 → 数据2 ├─→ 并行执行
程序3 → 数据3 ┘
```

### 2.4 调度策略

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| **FIFO** | 先进先出 | 简单场景 |
| **优先级** | 根据优先级调度 | 有优先级需求 |
| **依赖感知** | 考虑任务依赖 | 复杂依赖关系 |
| **资源感知** | 考虑资源限制 | 资源受限场景 |

## 3. 内存管理机制

### 3.1 定义与作用

**定义**：运行时内存分配、重用、优化的系统。

**作用**：
- 优化内存使用
- 减少内存分配开销
- 支持内存重用
- 管理内存层级

### 3.2 内存层级管理

#### 3.2.1 L0/L1/L2内存层级

**定义**：不同速度和容量的内存层级。

**层级说明**：
- **L0（寄存器）**：最快，容量最小
- **L1（片上缓存）**：较快，容量中等
- **L2（片外内存）**：较慢，容量最大

**优化策略**：
- 热点数据放在L0/L1
- 冷数据放在L2
- 根据访问模式优化

### 3.2.2 内存重用（Memory Reuse）

**定义**：重用已分配内存的优化机制。

**重用策略**：
- 生命周期分析
- 别名分析
- 工作空间重用

**详细说明**：见 [内存与资源机制详解](04-memory-resource.md)

### 3.3 内存优化（Memory Optimization）

**优化技术**：
- 内存对齐
- 内存池化
- 内存预分配
- 内存压缩

## 4. 同步机制

### 4.1 定义与作用

**定义**：多核并行执行时的同步机制，确保数据一致性和执行顺序。

**作用**：
- 确保数据一致性
- 控制执行顺序
- 协调并行执行
- 避免竞态条件

### 4.2 关键操作

#### 4.2.1 Barrier（屏障）

**定义**：同步屏障，等待所有线程到达屏障点。

**使用场景**：
- 阶段同步
- 数据准备完成
- 并行阶段切换

**示例**：
```cpp
// 所有线程在此等待
barrier.wait();

// 所有线程到达后继续执行
```

#### 4.2.2 Sync（同步）

**定义**：同步操作，确保操作完成。

**使用场景**：
- 内存同步
- 设备同步
- 数据同步

#### 4.2.3 Wait（等待）

**定义**：等待操作完成。

**使用场景**：
- 等待异步操作
- 等待依赖任务
- 等待资源释放

### 4.3 同步模式

| 模式 | 说明 | 使用场景 |
|------|------|---------|
| **Barrier同步** | 所有线程等待 | 阶段切换 |
| **点对点同步** | 两个线程同步 | 数据传递 |
| **条件同步** | 条件满足后同步 | 条件等待 |
| **异步同步** | 异步操作同步 | 异步执行 |

## 5. Launcher机制

### 5.1 定义与作用

**定义**：任务启动和执行的抽象机制，提供统一的任务启动接口。

**作用**：
- 统一任务启动接口
- 支持多种执行模式
- 抽象执行细节
- 简化任务管理

### 5.2 关键组件

#### 5.2.1 DeviceLauncher（设备端启动器）

**定义**：设备端任务的启动器。

**职责**：
- 启动设备端任务
- 管理设备资源
- 处理设备错误
- 返回执行结果

**代码位置**：
- `framework/src/machine/runtime/`

#### 5.2.2 EmulationLauncher（仿真启动器）

**定义**：仿真模式的启动器。

**职责**：
- 启动仿真任务
- 模拟设备执行
- 收集性能数据
- 验证正确性

**使用场景**：
- 开发调试
- 性能分析
- 功能验证

#### 5.2.3 CostModelLauncher（代价模型启动器）

**定义**：代价模型模式的启动器。

**职责**：
- 启动代价模型任务
- 估算执行时间
- 分析资源使用
- 优化建议

**使用场景**：
- 性能预测
- 资源规划
- 优化分析

### 5.3 Launcher选择

**选择策略**：
```
检查执行模式
    ├─→ NPU模式 → DeviceLauncher
    ├─→ SIM模式 → EmulationLauncher
    └─→ CostModel模式 → CostModelLauncher
```

### 5.4 Launcher接口

**统一接口**：
```cpp
class Launcher {
public:
    virtual void Launch(Task& task) = 0;
    virtual void Wait(Task& task) = 0;
    virtual Result GetResult(Task& task) = 0;
};
```

### 6.1 机制协作流程

```
编译后的Function
    ↓
执行调度机制
    ├─→ 任务分解
    ├─→ 资源分配
    └─→ 依赖管理
    ↓
Launcher机制
    ├─→ 选择启动器
    └─→ 启动任务

内存管理机制
    ├─→ 内存分配

    ↓
同步机制
    ├─→ 同步点
    └─→ 数据一致性
```

| 机制 | 依赖 | 被依赖 |
|------|------|--------|
| **执行调度** | - | Launcher、同步 |
| **内存管理** | - | 执行调度 |
| **同步机制** | 执行调度 | - |
| **Launcher** | 执行调度 | - |

## 7. 使用示例

### 7.1 执行调度示例

```python
import pypto.frontend as fe

@fe.jit
def compute(x: fe.Tensor[100, 100]):
    # 执行调度机制自动管理任务调度
    a = x + 1
    b = a * 2
    return b

# 执行时自动进行任务调度
result = compute(data)
```

### 7.2 同步操作示例

```python
@fe.jit
def parallel_compute(x: fe.Tensor[100, 100]):
    # 并行执行多个操作
    a = x + 1
    b = x * 2
    c = x - 1
    
    # 同步点：等待所有操作完成
    # 同步机制自动处理
    return a + b + c
```

### 7.3 Launcher选择示例

```python
import pypto

# 选择执行模式
pypto.set_host_options(
    run_mode=0,  # 0=NPU, 1=SIM, 2=COMPILE_ONLY
)

# Launcher机制根据run_mode自动选择
result = compute(data)
```

## 8. 常见问题

### 8.1 执行调度相关问题

**Q: 如何控制任务调度顺序？**

A: 通过操作依赖关系自动控制。也可以使用同步机制显式控制。

**Q: MPMD和SPMD有什么区别？**

A: MPMD是多个不同程序处理不同数据，SPMD是同一个程序处理不同数据。PyPTO使用MPMD模型。

### 8.2 内存管理相关问题

**Q: 运行时内存管理会影响性能吗？**

A: 内存管理机制经过优化，开销很小。内存重用可以显著提升性能。

**Q: 如何监控内存使用？**

A: 使用性能分析工具，或查看编译日志中的内存信息。

### 8.3 同步相关问题

**Q: 同步操作的开销大吗？**

A: 同步操作有一定开销，但对于确保正确性是必需的。优化依赖关系可以减少同步点。

**Q: 如何避免死锁？**

A: 避免循环依赖，使用统一的同步顺序，合理设计同步点。

### 8.4 Launcher相关问题

**Q: 如何选择Launcher？**

A: 根据执行模式自动选择。NPU模式使用DeviceLauncher，SIM模式使用EmulationLauncher。

**Q: 可以自定义Launcher吗？**

A: 可以，但需要实现Launcher接口并注册到系统中。

## 总结

PyPTO运行时机制通过执行调度、内存管理、同步和Launcher四个核心机制的协同工作，实现了高效的任务执行：

1. **执行调度机制**：MPMD模型，管理任务调度和资源分配
2. **内存管理机制**：优化内存使用，支持内存重用
3. **同步机制**：确保数据一致性和执行顺序
4. **Launcher机制**：统一的任务启动接口

理解这些机制有助于：
- 深入理解运行时工作原理
- 优化执行性能
- 调试运行时问题
- 扩展运行时功能

# Glossary

| Term/Abbreviation | Meaning                                                      |
| ----------------- | ------------------------------------------------------------ |
| **PyPTO**         | PyPTO is a high-performance programming framework for CANN that adopts the PTO programming paradigm, designed to simplify the operator development workflow while retaining high-performance computing capabilities. |
| **PTO**           | PTO (Parallel Tensor/Tile Operation) is a tensor-based programming paradigm. The core idea is to use tensors as the basic representation of data, and to describe and assemble a complete computation process (or computation graph) through a series of basic tensor operations. |
| **Operation**     | The unit that describes the basic operations in the computation graph in PyPTO. Each Operation defines a specific computation logic that can process input tensors and generate output tensors. By combining different Operations, complex computation logic can be implemented. |
| **Computation Graph** | The complete compilation process of a PyPTO program from abstract computation description to hardware execution. |
| **Tensor Graph**  | The Tensor Graph consists of tensor and operation nodes and is used to describe the computation process defined by the user. This graph does not involve low-level semantics such as tile expansion and memory hierarchy, and serves only as the expression of high-level computation logic. Optimizations based on the Tensor Graph focus primarily on hardware-independent general graph optimization techniques, such as redundant node elimination and constant folding. |
| **Tile Graph**    | The Tile Graph consists of tiles and TileOps. The Tensor Graph is expanded based on TileShape, decomposing tensors into tiles and operations into TileOps. The Tile Graph automatically infers the storage location of tiles based on TileOp information and the target hardware's memory hierarchy, and inserts memory transfer nodes when necessary to ensure correct data transfer between different memory hierarchy levels. |
| **Block Graph**   | The Block Graph partitions the Tile Graph into multiple subgraphs, allowing each subgraph to be scheduled to run on a single AI Core. The Block Graph is used for hardware-related optimizations, including instruction scheduling, on-chip memory allocation, synchronization operation insertion, etc., to improve hardware execution efficiency. |
| **Execute Graph** | The Execute Graph is the final product of the compilation process. It integrates all optimization results and precisely describes the dependency relationships between all Block Graphs, used for scheduling and execution by the device scheduler. |
| **Swimlane Graph** | The swimlane graph provides an intuitive display of the actual scheduling and execution process of the computation graph. Through the IDE's visualization interface, developers can observe data flow paths, dependency relationships between operations, and potential performance bottlenecks, enabling more efficient analysis and optimization of operator execution performance. |
| **TileShape**     | A parameter in PyPTO used to define the shape of tensor tiling (partitioning), which determines the parallelism granularity and data partitioning pattern of operations on hardware. By properly configuring TileShape, memory usage and computation efficiency can be optimized, allowing the computation process to better adapt to hardware characteristics. |
| **Pass**          | A stage in PyPTO used for compile-time optimization of computation graphs to improve execution efficiency and hardware utilization. Each Pass can perform specific optimization operations on the computation graph, such as graph simplification, operator fusion, and scheduling optimization. |
| **Graph Merging** | The process of merging multiple logically independent Operations in a computation graph into a single logical subgraph, which ultimately generates one physical compute kernel. It is mainly divided into depth-direction merging and breadth-direction merging. |
| **Isomorphic Subgraph** | A local fragment in the computation graph with completely identical topology and operator types. |
| **Isomorphic Subgraph Group** | A collection of fragments that are mutually isomorphic subgraphs, called an isomorphic subgraph group. During breadth-direction graph merging pass processing, a unique characteristic identifier — the hashorder — is generated for each group of isomorphic subgraphs. |
| **stitch**        | Breaking the boundaries of multiple loop cycles, stitching together multiple leaf function execution tasks with no dependency relationships into a single large task for unified submission, reducing synchronization overhead and improving scheduling performance. |

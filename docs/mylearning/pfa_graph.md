### 3.2 Block组装过程

```python
# 代码位置: glm_attention_ifa_pfa_opt_v2.py:580-590

kj_assemble = pypto.tensor([s2_tile, dn], k_2d.dtype, "kj_assemble")
vj_assemble = pypto.tensor([s2_tile, dn], v_2d.dtype, "vj_assemble")

for i in range(block_num):  # block_num = s2_tile // block_size = 1
    block_idx = block_table[b_idx, idx + i]
    block_idx_valid = block_idx.max(0)  # -1 → 0
    
    # 组装 K
    kj_assemble[i * block_size:(i + 1) * block_size, 0:] = \
        pypto.view(k_2d, [block_size, dn], [block_idx_valid * block_size, 0])
    
    # 组装 V
    vj_assemble[i * block_size:(i + 1) * block_size, 0:] = \
        pypto.view(v_2d, [block_size, dn], [block_idx_valid * block_size, 0])
```

## 4. 五层循环迭代结构

### 4.1 循环嵌套图

```
┌─────────────────────────────────────────────────────────────────┐
│ for b_idx in range(b):              # batch 维度 (0 ~ 7)        │
│ ┌─────────────────────────────────────────────────────────────┐ │
│ │ for s1_idx in range(s1):          # query位置 (0 ~ 127)     │ │
│ │ ┌─────────────────────────────────────────────────────────┐ │ │
│ │ │ cur_seq = s1_idx + 1    # 因果注意力: KV长度递增        │ │ │
│ │ │ s2_loop = ceil(cur_seq / s2_tile)                      │ │ │
│ │ │ ┌─────────────────────────────────────────────────────┐ │ │ │
│ │ │ │ for n2_idx in range(nkv):   # KV head (0)           │ │ │ │
│ │ │ │ ┌─────────────────────────────────────────────────┐ │ │ │ │
│ │ │ │ │ for g_idx in range(g_loop): # Q head组 (0)      │ │ │ │ │
│ │ │ │ │ ┌─────────────────────────────────────────────┐ │ │ │ │ │
│ │ │ │ │ │ 初始化: oi_update, sum_update, max_update  │ │ │ │ │ │
│ │ │ │ │ │ ┌─────────────────────────────────────────┐ │ │ │ │ │ │
│ │ │ │ │ │ │ for s2_idx in range(s2_loop):           │ │ │ │ │ │ │
│ │ │ │ │ │ │ │  # KV 分块迭代 (Flash Attention核心)  │ │ │ │ │ │ │
│ │ │ │ │ │ │ │  1. 组装 K/V block                    │ │ │ │ │ │ │
│ │ │ │ │ │ │ │  2. QK^T 计算                        │ │ │ │ │ │ │
│ │ │ │ │ │ │ │  3. Online Softmax                   │ │ │ │ │ │ │
│ │ │ │ │ │ │ │  4. PV 计算                          │ │ │ │ │ │ │
│ │ │ │ │ │ │ └─────────────────────────────────────────┘ │ │ │ │ │ │
│ │ │ │ │ │ │ 输出: oi_final = oi_update / sum_update    │ │ │ │ │ │
│ │ │ │ │ │ └─────────────────────────────────────────────┘ │ │ │ │ │
│ │ │ │ │ └─────────────────────────────────────────────────┘ │ │ │ │
│ │ │ │ └───────────────────────────────────────────────────┘ │ │ │
│ │ │ └───────────────────────────────────────────────────────┘ │ │
│ │ └───────────────────────────────────────────────────────────┘ │
│ └───────────────────────────────────────────────────────────────┘
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 循环变量说明

| 循环层 | 变量 | 范围 | 作用 |
|--------|------|------|------|
| 1 | `b_idx` | 0 ~ b-1 | 遍历 batch |
| 2 | `s1_idx` | 0 ~ s1-1 | 遍历 query 序列位置 |
| 3 | `n2_idx` | 0 ~ nkv-1 | 遍历 KV head |
| 4 | `g_idx` | 0 ~ g_loop-1 | 遍历 Q head 组 |
| 5 | `s2_idx` | 0 ~ s2_loop-1 | 遍历 KV 分块 |

### 4.3 关键偏移量计算

```python
# 代码位置: glm_attention_ifa_pfa_opt_v2.py:572-574

# Block 索引
idx = s2_idx * block_num  # s2_idx * 1 = s2_idx

# Batch-Sequence 偏移 (定位到具体 token)
bs_ofs = b_idx * s1_scalar + s1_idx
# 例如: b_idx=1, s1_idx=50 → bs_ofs = 1*128 + 50 = 178

# Head 组偏移 (定位到具体 head)
n1g_ofs = n2_idx * group + g_idx * g_tile
# 例如: n2_idx=0, g_idx=0, group=12 → n1g_ofs = 0

# 输出偏移 (写入结果的位置)
oi_ofs = [bs_ofs, n1g_ofs, 0]
# 例如: [178, 0, 0] → 写入 atten_out[178, 0:12, 0:128]
```

## 5. 因果注意力实现

### 5.1 因果掩码原理

```
因果注意力: Q[i] 只能看到 K[0:i+1] 和 V[0:i+1]

序列位置:    0    1    2    3   ...   127
           ┌────┬────┬────┬────┬─────┬─────┐
Q[0] ────> │ ✓  │ ✗  │ ✗  │ ✗  │ ... │ ✗   │  cur_seq = 1
           ├────┼────┼────┼────┼─────┼─────┤
Q[1] ────> │ ✓  │ ✓  │ ✗  │ ✗  │ ... │ ✗   │  cur_seq = 2
           ├────┼────┼────┼────┼─────┼─────┤
Q[2] ────> │ ✓  │ ✓  │ ✓  │ ✗  │ ... │ ✗   │  cur_seq = 3
           ├────┼────┼────┼────┼─────┼─────┤
Q[3] ────> │ ✓  │ ✓  │ ✓  │ ✓  │ ... │ ✗   │  cur_seq = 4
           ├────┼────┼────┼────┼─────┼─────┤
  ...      │ ...│ ...│ ...│ ...│ ... │ ... │
           ├────┼────┼────┼────┼─────┼─────┤
Q[127] ──> │ ✓  │ ✓  │ ✓  │ ✓  │ ... │ ✓   │  cur_seq = 128
           └────┴────┴────┴────┴─────┴─────┘

公式: cur_seq = s1_idx + 1
```

### 5.2 cur_seq 与 s2_loop 的关系

```
s1_idx  │ cur_seq  │ s2_loop = ceil(cur_seq/128)  │ KV blocks 需要处理
────────┼──────────┼──────────────────────────────┼────────────────────
   0    │    1     │         1                    │ 1 个 (部分)
   1    │    2     │         1                    │ 1 个 (部分)
  ...   │   ...    │        ...                   │ ...
  127   │   128    │         1                    │ 1 个 (完整)
────────┴──────────┴──────────────────────────────┴────────────────────

当 s1 = 128, s2_tile = 128 时:
- 每个 query 位置最多只需要处理 1 个 KV tile
- 但 effective tile size 不同 (actual_s2_tile)
```

### 5.3 actual_s2_tile 计算

```python
# 代码位置: glm_attention_ifa_pfa_opt_v2.py:574
actual_s2_tile = (cur_seq - s2_idx * s2_tile).min(s2_tile)
```

```
示例: s1 = 128, s2_tile = 128

s1_idx │ cur_seq │ s2_idx │ actual_s2_tile
───────┼─────────┼────────┼────────────────
   0   │    1    │   0    │  min(1, 128) = 1
   1   │    2    │   0    │  min(2, 128) = 2
   5   │    6    │   0    │  min(6, 128) = 6
  50   │   51    │   0    │  min(51, 128) = 51
 127   │   128   │   0    │  min(128, 128) = 128

actual_s2_tile 表示当前 tile 中有效的 KV 数量
用于 valid_shape 标记，避免计算无效位置
```

## 7. Online Softmax增量更新

### 7.1 算法原理

```
标准 Softmax:
  softmax(x_i) = exp(x_i) / Σ_j exp(x_j)

问题: 需要先计算所有 x_j 的 max 和 sum，无法分块

Online Softmax 解决方案:
  分块计算，增量更新 max 和 sum

假设已处理块:
  - max_old, sum_old, output_old

新块计算:
  - max_new = max(max_old, max_current)
  - correction = exp(max_old - max_new)
  - sum_new = sum_old * correction + sum_current
  - output_new = output_old * correction + output_current
```

### 7.3 数值稳定性说明

```
为什么需要 max 校正?

假设 sij_scale = [100, 101, 102]

直接计算:
  exp([100, 101, 102]) = [2.7e43, 7.3e43, 1.98e44]  ← 溢出!

数值稳定版本:
  max = 102
  exp([100, 101, 102] - 102) = exp([-2, -1, 0])
                             = [0.135, 0.368, 1.0]  ← 正常

增量更新时:
  旧 max = 100, 新 max = 102
  correction = exp(100 - 102) = exp(-2) = 0.135
  旧的 sum 和 output 需要乘以 0.135 来校正
```

### 9.2 关键优化技术

#### 9.2.1 nbuffer 模式

```python
# v2 新增: Cube 和 Vector 单元的 nbuffer 模式
"cube_nbuffer_mode": 1,
"cube_nbuffer_setting": {-1: 8},  # 全局 8 缓冲

"vec_nbuffer_mode": 1,
"vec_nbuffer_setting": {},
```

**优化原理**:
- 多缓冲区机制，减少流水线停顿
- 8 个缓冲区轮换使用，隐藏内存延迟
- 读写操作并行化，提升带宽利用率

#### 9.2.2 L1 缓存复用

```python
# v2 新增: 全局 L1 复用模式
"cube_l1_reuse_mode": 1,
"cube_l1_reuse_setting": {-1: 8},  # 全局复用 8 次
```

**优化原理**:
- Q 矩阵常驻 L1 Cache
- 减少全局内存访问次数
- 特别适用于多次 s2_idx 迭代场景

#### 9.2.3 pg_upper_bound 提升

```python
# v1: pg_upper_bound = 1536
# v2: pg_upper_bound = 10000  ← 大幅提升
```

**优化原理**:
- 允许更大的子图（Program Graph）
- 减少子图切分次数
- 提升指令级并行度

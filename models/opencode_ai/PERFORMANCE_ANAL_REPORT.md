## 性能瓶颈分析

### 主要问题

1. **线程利用率较低 (67.5%)**
   - 大部分线程的工作时间在 20-25us 之间
   - 等待调度时间在 7-15us 之间，占比较高
   - 等待前驱时间相对较小（0-4us）

2. **气泡率较高 (~32.5%)**
   - 气泡率 = 100% - 线程利用率 = 32.5%
   - 远超目标值 5%
   - 主要原因是等待调度时间过长

3. **任务调度不均衡**
   - AIV_40 和 AIV_41 的利用率最低（~60%）
   - AIV_21 和 AIV_22 的利用率最高（~95%）
   - 表明任务分配不均衡

### 性能优势

1. **控制开销极低 (1.0%)**
   - 控制开销占比仅为 1.0%，远优于目标值 30%
   - 说明 AICPU 控制流程非常高效

2. **总执行时间合理 (421.52us)**
   - 对于 batch_size=32, hidden_dim=4096 的规模，执行时间在合理范围内

## 性能优化建议

### 1. 任务调度优化 (高优先级)

**问题**: 等待调度时间过长（7-15us）

**建议**:
- 调整 `device_sched_mode` 参数，尝试不同的调度模式
- 当前使用 `device_sched_mode=1`，可以尝试 `device_sched_mode=0` 或 `device_sched_mode=2`
- 优化任务依赖关系，减少任务间的等待时间

**实施方法**:
```python
@pypto.frontend.jit(
    runtime_options={
        "device_sched_mode": 0,  # 尝试不同的调度模式
        "stitch_cfgcache_size": 2700000
    },
    debug_options={"runtime_debug_mode": 1}
)
```

### 2. 任务并行化优化 (高优先级)

**问题**: 任务分配不均衡，部分线程利用率低

**建议**:
- 增加任务并行度，让更多任务能够并行执行
- 优化 tile size，提高内存利用率
- 考虑使用双缓冲技术

**实施方法**:
- 调整 `LstmTileConfig` 中的 tile 参数
- 增加展开列表中的展开因子

### 3. 内存优化 (中优先级)

**问题**: 峰值内存使用为 0 bytes（可能需要重新采集）

**建议**:
- 调整 tile size 提高内存利用率
- 优化内存分配策略
- 考虑内存复用



### 4. 计算优化 (中优先级)

**问题**: 部分线程的工作时间较长（28us）

**建议**:
- 优化算子实现逻辑
- 使用更高效的 API
- 考虑向量化优化

**具体优化方向**:
- GELU 激活函数优化（从气泡分析看，gelu_activation_core 占用较多时间）
- RMSNorm 优化
- 减少不必要的中间变量

### 5. 已知限制

- FP16 精度损失：使用 FP16 数据类型可能带来一定的精度损失
- 当前实现未使用双缓冲技术，可能影响性能
